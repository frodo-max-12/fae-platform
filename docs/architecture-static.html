FAE Platform

From a customer's RFQ email to a technical proposal in minutes — a five-step wizard for field application engineers, backed by pre-built catalogs for 54 brands.
The catalog-first rule. Pre-built JSON catalogs answer first, fast and deterministic. The LLM ranks and explains; the code verifies every spec. Live dealer sites are fetched only when a catalog is missing.
Intake›Extract›Match›Compare›Send one email in, one proposal out

The wizard

— what the engineer walks through
1

Email intake

Sign in with Google OAuth · fetch from Gmail by date range or search, paginated to 1,000 · HTML parsed to text with tables and quoted threads intact · PDF, Excel and CSV attachments pulled in · or paste a raw RFQ

api/gmail · attachmentParse.ts
›
2

Requirement extraction

Two passes: the first extracts every line item (MPN, specs, quantity, price, delivery, application) across 11+ input formats · the second audits the first for missed specs and misread numbers · structured JSON out

api/extract
›
3

Product matching

Brand-locked or AI mode across 54 brands · catalog first · tiered MPN_EXACT › MPN_XREF › BRAND_LOCKED › SPECS › NO_MATCH · up to 5 ranked matches with a 0–100 score and per-spec compliance · SHA-1 cache

api/products · catalogStore.ts
›
4

Compare + draft

Parametric table shaped by category — MOSFETs get Rds(on)/Vds/Qg, MCUs get Flash/RAM/Clock · six verdicts per row · overall score and cost saving · a proposal email with the table, advantages, terms and a samples offer

api/compare · api/draft
›
5

Review + send

Engineer edits the draft · sent through the Gmail API on the same OAuth session · request saved with the full audit trail · interrupted workflows resume where they stopped

api/gmail/send · persistProgress.ts

Under the hood

— what every step leans on
CAT

Catalog engine

59 JSON catalogs built from dealer sites · fetch-all-brands, enrich, retry-empty and rebuild-index scripts · a live fetcher as fallback · refresh from the CLI or an API endpoint

data/catalog/ · scripts/ · catalogBuild.ts
LLM

Model layer

One client with retry and backoff · prompts for extraction, self-audit, matching, comparison and drafting · every numeric claim checked in code after the model answers

lib/gemini.ts · api/*
ID

Identity + mail

Google OAuth 2.0 · tokens kept in encrypted HTTP-only cookies, never in the browser · Gmail read and send scopes · expiry refresh on the server

api/auth · api/gmail
DB

Persistence

Prisma over SQLite · requests, history and every intermediate step · wizard state autosaved · match cache keyed by content hash

prisma/ · lib/db.ts · lib/store.ts
DOC

Attachment parsing

PDF datasheets, Excel BOMs and CSV parsed to text with tables preserved · fed into extraction alongside the email body

attachmentParse.ts · pdf-parse · xlsx
